# 1. 项目概述

## 1.1 一句话定义

**Samsara 是一个可安全自我修改、经验可复利、多会话并行的自进化智能体运行时**——用可逆可组合的插件内核做骨架，用技能资产化做肌肉，用受分级授权约束的元改进层做递归火种。

## 1.2 设计思想来源

| 来源 | 吸收的能力 | 在 Samsara 中的位置 |
|---|---|---|
| DSH / Cordis | 时间可组合性（可逆效应）、空间可组合性（反应式余效应）、汇流性 | L0 内核 |
| Hermes Agent | 技能文件沉淀、Curator 保鲜、GEPA 离线优化、人审闸门 | L2 / L3 |
| RSI 理论 | 递归自我改进的终局视角与安全警示 | L3 的分级约束 |
| OpenClaw Gateway | 渠道接入、会话路由、节点能力、三层信任栈 | L0.5 接入平面 |

## 1.3 核心设计原则（宪法性原则，不可在评审外修改）

### 价值原则（用户视角——系统为什么值得用）

- **V1 简单便捷**：新用户第一天只需要会"说话"，不需要会"配置"。落点：渠道即主界面、模型自动路由（附录 E）、自然语言创建定时任务（附录 C）、姿态预设一键切换。
- **V2 高效准确**：同类任务第 N 次的成本与耗时必须显著低于第 1 次——复利曲线是可测量的验收指标。落点：三级固化（附录 F）、任务-模型记分卡（E.2）、技能复利、并行会话与子 Agent。
- **V3 灵活性高**：用户的即兴技巧永远不需要绕过架构——架构追认技巧，而不是封堵技巧。落点：一切皆插件与热插拔、`trust link` 一等操作、完全访问模式作为合法逃生门。

### 结构原则（系统视角——价值原则怎么不翻车）

1. **一切自我修改必须可逆**：任何对系统状态的修改登记逆操作，可按 LIFO 回滚。
2. **一切依赖只声明、不接线**：组件生命周期由运行时反应式驱动。
3. **一切资产可审计**：技能、记忆、提示词均为带版本树的文本资产。
4. **权力只收敛不扩散**：子代能力 ⊆ 父代；配额随层级递减；安全闸在递归可达范围之外。
5. **边缘并行、内核串行**：并行发生在会话/子 Agent 分支内部，共享状态写入经单一串行账本。
6. **探索在分支，合并在闸门**：新经验默认局部，晋升需通过影子验证与 R 等级授权。

### 冲突裁决规则

> 当价值原则与结构原则冲突时：**灵活性（V3）优先于防控性默认；但一切让位于可逆性（结构 1）与账本诚实（结构 5）。**
> 即：可以放手干（V3），可以不打断（V1），但不可以不留痕、不可以不可回滚——不留痕会毁掉复利（V2 的根基），不可回滚会毁掉放手（V3 的底气）。结构原则不是价值原则的税，而是它们的发动机。

### 姿态预设（Posture Presets）

```yaml
posture: 效率优先   # 默认模式=自动编辑；"完全访问"时效设为 4h（≤上限）；R0–R2 全自动；R3 摘要式批量审
posture: 谨慎优先   # 默认模式=变更前确认；R1+ 逐条人审；高危双人复核
posture: 自定义     # 逐项展开；架构强制的仅 R5 最小核心
```

> 注（INC1）：模式时效数值——"完全访问"默认 30 分钟、硬上限 4 小时、效率预设取 4h——的唯一权威是《接口设计文档》§3.4 时效权威表；本文及其他文档中出现的数字均为示意。

## 1.4 名词表

| 术语 | 定义 |
|---|---|
| Effect（可逆效应） | 组件对环境的一次修改，携带逆操作 |
| Coeffect（反应式余效应） | 组件对环境资源的声明式依赖，由运行时解析并驱动生命周期 |
| 串行账本（Ledger） | L0 的唯一写入通道，所有 effect 按序登记 |
| 技能（Skill） | 以 `SKILL.md` 形式存在的可复用经验文本资产 |
| 局部技能 / 全局技能 | 分支内可见 / 经晋升闸进入全局库的技能 |
| Curator | 技能库保鲜进程，驱动技能状态机流转 |
| R 等级（R0–R5） | 修改风险分级，决定通过门槛 |
| 影子验证（Shadow Verification） | 候选变体挂载影子分支、回放真实轨迹对打的验证方式 |
| 会话分支（COW Overlay） | 会话/子 Agent 的写时复制隔离层 |
| 授权代数 | 子 Agent 能力衰减的三条不等式（见 5.4） |
| 信任栈 | Token → 设备签名 → 配对审批 的三层认证 |
| 宪法层 | R5，硬编码禁止自我修改的安全闸集合 |

# 2. 总体架构

## 2.1 分层视图

```
┌──────────────────────────────────────────────────────────┐
│ L3 元改进层（RSI 火种）                                    │
│    反思器 / GEPA 优化器 / R 等级闸 / 影子验证器 / 宪法层    │
├──────────────────────────────────────────────────────────┤
│ L2 经验资产层（Hermes 肌肉）                               │
│    技能库（Git化）/ 记忆分层 / Curator / 晋升管道          │
├──────────────────────────────────────────────────────────┤
│ L1 执行层（Agent 本体 × N）                                │
│    任务回路 / 轨迹记录器 / 并行会话 / 子Agent 派生器        │
├──────────────────────────────────────────────────────────┤
│ L0.5 接入平面（Gateway 器官）                              │
│    渠道插件 / sessionKey 路由 / 车道队列 / 节点 / 信任栈   │
├──────────────────────────────────────────────────────────┤
│ L0 可组合内核（DSH 骨架）                                  │
│    Context / 可逆效应 / 反应式余效应 / 串行账本 / 事件溯源  │
└──────────────────────────────────────────────────────────┘
              人类站在 L3 门口，手握总闸
```

## 2.2 层间契约

| 上层 ↓ 使用 → 下层 | L0.5 | L1 | L2 | L3 |
|---|---|---|---|---|
| **L0 提供** | 插件生命周期、消息总线、信任栈原语 | 分支隔离、轨迹事件 | 资产版本存储原语 | 账本审计接口 |
| **L0.5 提供** | — | 会话消息流、节点能力 | 交互信号（用于技能评估） | 真实消息流（影子验证考场） |
| **L1 提供** | — | — | 任务轨迹（技能沉淀原料） | 轨迹种群（优化食料） |
| **L2 提供** | — | 技能/记忆检索 | — | 元对象清单（技能生成器等） |

**铁律**：禁止跨层直接访问（如 L1 不得直接读写 L0 账本）；一切层间交互经公开接口。

## 2.3 关键不变量（Invariant）

- **INV-1（汇流性）**：任意激活/停用序列的静止态 ≡ 按依赖序一次性组合最终集合的状态。
- **INV-2（可逆性）**：任意时刻可将系统回滚至任意历史快照，包括"回滚一次回滚"。
- **INV-3（能力单调衰减）**：沿派生链，能力集合只减不增。
- **INV-4（单写入者）**：共享状态的写入仅经 L0 账本串行发生。
- **INV-5（宪法不可触达）**：R5 集合在运行时可枚举、可校验，且无任何运行路径可修改。

# 3. L0 可组合内核

## 3.1 职责

插件生命周期管理、依赖解析、副作用记账与回滚、事件溯源、系统级不变量维护。

## 3.2 核心抽象

### 3.2.1 Context（组件上下文）

每个插件获得一个 `Context` 句柄，是其与系统交互的**唯一**通道：

```ts
interface Context {
  // 声明依赖（余效应）：由运行时解析，驱动激活/停用
  inject<T>(service: ServiceKey<T>): ServiceHandle<T>;

  // 登记副作用（可逆效应）：必须携带逆操作
  effect<T>(desc: string, apply: () => T, revert: (t: T) => void): EffectToken;

  // 提供能力给其它组件
  provide<T>(service: ServiceKey<T>, impl: T): void;

  // 发射/订阅事件（经总线，不直接互调）
  emit(event: TypedEvent): void;
  on<T>(event: EventKey<T>, handler: (e: T) => void): Disposable;
}
```

### 3.2.2 可逆效应（Revertible Effects）

- 每次 `ctx.effect` 调用将 `(apply, revert)` 对记入所属插件的**效应栈**。
- 卸载插件时，内核按 **LIFO** 逐条执行 `revert`。
- `revert` 必须满足：执行后环境状态 ≡ `apply` 之前的状态（由 3.4 的契约测试强制）。
- 示例（注册一个工具）：

```ts
ctx.effect("register tool: web_search",
  () => toolRegistry.add(webSearchTool),
  (token) => toolRegistry.remove(token));
```

### 3.2.3 反应式余效应（Reactive Coeffects）

- 组件只声明"我需要什么"，不轮询、不接线。
- 内核维护依赖图；服务出现 → 激活依赖方；消失 → 先停用依赖方；被替换 → 平滑重启依赖方。
- 生命周期保证：**B 依赖 A ⇒ B 只在 A 就绪后激活，在 A 停止前停用，A 失败时 B 不启动。**

### 3.2.4 串行账本（Effect Ledger）

- 所有 `effect` / 插件启停 / 依赖变更，以追加日志形式写入**单一日志流**。
- 账本即系统状态的真相来源；内存状态是账本的重放投影（event sourcing）。
- 账本条目：`{seq, ts, actor, kind, payloadHash, prevHash}`，哈希链防篡改。

### 3.2.5 插件清单（Manifest）

```yaml
# plugin.yaml
name: skill-store
version: 0.3.1
provides: [skill-store]
requires:
  - ledger        # 必需依赖
  - event-bus
optional-requires:
  - vector-index  # 可选依赖，缺席时降级
r-level: R2       # 修改本插件所需授权等级
```

## 3.3 生命周期状态机

```
installed → resolved → active ⇄ suspended → disposed
              │            │
              └─ failed ───┘（自动回滚至 installed）
```

- 状态迁移全部经账本登记，失败迁移触发自动回滚。
- 内核崩溃恢复：重放账本至最近快照，重建内存状态。

## 3.4 内核质量保障

- **契约测试**：对每个插件的每条 effect，测试 `apply → revert` 后环境哈希不变。
- **汇流性 property-based test**：随机生成激活/停用序列，断言终态与一次性组合等价（INV-1）。
- **模糊测试**：随机杀死进程、随机延迟依赖，验证恢复路径。

# 4. L0.5 接入平面（Gateway 移植层）

> 移植自 OpenClaw Gateway 的四个器官，全部以 **L0 特权插件**形式存在，因此天然获得热插拔与崩溃重建能力。

## 4.1 渠道插件（Channel Adapters）

### 职责
将外部消息平台（WhatsApp / Telegram / Slack / WebChat / …）归一化为内部 `InboundMessage`，并将 `OutboundMessage` 送达对应平台。

### 接口

```ts
interface ChannelAdapter {
  id: string;                    // "telegram"
  capabilities: ChannelCaps;     // 富文本? 语音? 群组?
  start(ctx: Context): Promise<void>;
  normalize(raw: unknown): InboundMessage;
  deliver(msg: OutboundMessage): Promise<Receipt>;
}
```

### 热插拔语义（相对 Gateway 原生版的升级）

- **拔出**：逆操作注销监听器 → 排空该渠道车道队列 → 完成已受理消息的回执 → 断开连接。
- **插入**：声明依赖（消息总线、凭据存储）→ 余效应自动接线。
- 渠道插件的启停列入 **R4 级保护**（见 7.2），防止攻击者诱导卸载安全渠道。

## 4.2 会话路由（Session Router）

- **sessionKey** 是路由选择器，格式：`<channel>:<scope>:<peer|group>`；`dmScope: per-channel-peer` 用于多用户收件箱隔离。
- **会话即隔离单元**：不同 sessionKey 的上下文永不互泄。
- **per-lane 车道队列**：同一 sessionKey 的消息串行派发，不同 lane 并行——并行度在 lane 间，竞态在结构上不存在。
- 会话 ↔ L2 分支映射：**一个活跃 sessionKey 绑定一条 COW 经验分支**（见 6.4）。

## 4.3 节点插件（Nodes）

设备能力（摄像头、录屏、系统命令、剪贴板……）以 Node 形式接入：

- Node 声明 `caps`（能力清单），通过 `node.invoke(cap, args)` 被调用。
- Node 与执行体遵循同一抽象：**Node 是无脑的子 Agent，子 Agent 是带脑的 Node**——共用能力声明与审批通道。
- 危险 cap（如 `shell.exec`）触发配对审批升档。

## 4.4 信任栈（Trust Stack）

| 层 | 机制 | 验证内容 |
|---|---|---|
| T1 | Gateway Token / 共享密钥 | 合法客户端 |
| T2 | 设备身份 + 挑战签名（绑定平台与设备族） | 合法设备 |
| T3 | 配对审批（非本地连接必须显式批准；回环可自动） | 主人认可 |

- 认证产物为**信任级别** `TrustLevel ∈ {owner, known, guest, untrusted}`，随消息一路携带，供授权矩阵（7.3）消费。
- **默认绑定 `127.0.0.1:18789`**；远程访问首选 Tailscale / SSH 隧道。该默认值属宪法层条款，Agent 无权修改。

## 4.5 WebSocket 协议（控制面）

```
握手：首帧必须是 hello（非 JSON / 非 hello 首帧 → 硬关闭）
  → {type:"hello", auth, device, role, caps, trustEvidence}
  → {type:"hello-ok", sessionTicket, ledgerSeq}

请求：{type:"req", id, method, params, idempotencyKey?}
响应：{type:"res", id, ok, result|error}
事件：{type:"event", seq, event, payload}
```

- 有副作用的 method（`send` / `agent.run`）**必须携带幂等键**，服务端短期去重缓存保证安全重试。
- 角色：`client`（控制面 UI/CLI）、`node`（设备）、`lane`（内部会话消费端）。

## 4.6 渠道表达力模型

> v0.6 增补。渠道不是纯文本管道，而是**能力上限各不相同的表达力阶梯**。

### 表达力阶梯（ChannelCaps 的语义）

| 层级 | 能力 | 典型支持 |
|---|---|---|
| L1 | 纯文本 | 全部 |
| L2 | 富文本（Markdown/代码块/链接） | Telegram、Slack、WebChat |
| L3 | 附件（图片/文件/语音/位置） | 几乎全部 |
| L4 | 交互组件（内联按钮、卡片、表单） | Telegram、Slack、WebChat 强；WhatsApp 弱 |
| L5 | 流式与状态（打字中、消息编辑、已读回执） | Telegram、WebChat |
| L6 | 双向音视频 / 富应用界面 | 多数渠道不支持；IDE 渠道可超此级 |

### 三条核心规则

1. **富类型消息模型 + 优雅降级**：Agent 产出富类型意图（Typed Blocks：文本/表格/按钮/附件），适配器按 ChannelCaps 逐级降级渲染（表格→图片/代码块→纯文本；按钮→内联键盘→"回复 1/2"）。Agent 不感知目标渠道——表达层与传输层解耦。
2. **入站按钮回调 = 带签名的结构化事件，绝不翻译为文本**：`Callback(actionId, signedPayload, evidence)` 直通信任栈验证后进入 R 闸。文本"同意"可伪造，签名回调不可——这是 HITL 审批能在聊天渠道中安全成立的前提，也是审计取证的基础。
3. **渠道双向**：渠道同时承载 Agent 主动推送（定时任务投递、熔断告警、每日摘要），推送时机由注意力路由器裁决（B.4）。

### 指挥型 / 共处型判据

- **指挥型**（下意图 → 看汇报 → 轻审批 → 收成品）：渠道表达力覆盖约 80% 场景，是主循环；
- **共处型**（共同检视复杂产物、逐行 diff、协同编辑）：超出 L4 天花板，归属高 caps 渠道或 WebUI。

### IDE / 终端作为渠道

渠道本质是"可互换传输层"，因此 **IDE 插件与终端可注册为高 caps 渠道**（diff 视图、文件树导航、流式日志）。同一份富类型意图（如"展示本次修改"）由路由按 caps 分发：在 IDE 渠道渲染为 diff 视图，在聊天渠道降级为摘要 + 附件。深度评审由此被渠道抽象收编，而非跳出架构。

# 5. L1 执行层

## 5.1 任务回路（Agent Loop）

标准 ReAct 变体，特殊之处在于**可观测性预埋**与**可中断性**：

```
loop:
  1. 装配上下文（系统提示 + 检索到的技能 + 相关记忆）
  2. LLM 推理 → 动作决策（工具调用 / 回复 / 派生子Agent）
  3. 执行动作（经 L0 effect 登记）
  4. 记录轨迹事件（见 5.2）
  5. 检查中断信号（回滚指令 / 配额耗尽 / 信任降级）
  until 任务完成 | 放弃 | 被回收
```

## 5.2 轨迹记录器（Trajectory Recorder）

每次任务产出结构化轨迹，写入事件溯源日志，供 L2/L3 消费：

```json
{
  "traceId": "tr_01J...",
  "sessionKey": "telegram:dm:owner",
  "skillsLoaded": ["skill://web-research@v3"],
  "steps": [{"kind": "tool", "name": "web_search", "ms": 1240, "ok": true}],
  "outcome": "success | failure | aborted",
  "failureAnalysis": null,
  "cost": {"tokens": 48210, "usd": 0.31},
  "durationMs": 184000
}
```

- 失败轨迹必须带 `failureAnalysis`（LLM 生成 + 规则校验），这是 L3 "理解为何失败"的原料。

## 5.3 并行会话

- 每个活跃会话是独立执行体，绑定独立 COW 分支（读全局、写本地）。
- 会话间**不共享内存态**，仅通过 L0 账本与 L2 全局库间接通信。
- 会话回收 = 插件卸载：逆操作回滚其对共享环境的一切副作用，分支进入合并或丢弃流程。

## 5.4 子 Agent 派生器（Spawner）与授权代数

### 派生接口

```ts
spawn(spec: {
  goal: string;
  capabilities: CapabilitySet;   // ⊆ caller.capabilities（强制校验）
  budget: { tokens: number; depth: number; wallMs: number }; // < caller.remaining
  rCeiling: RLevel;              // ≤ caller.rLevel，默认 R0
  branch: "cow" | "readonly";
}): ChildHandle
```

### 三条不变式（INV-3 的操作化）

```
child.capabilities ⊆ parent.capabilities      // 能力只减
child.budget       < parent.remainingBudget   // 配额递减 ⇒ 递归必然终止
child.rCeiling     ≤ parent.rLevel            // 动刀权限只降
```

### 配额递减树

```
主Agent (budget: 100%, depth: 0)
 ├─ 子A (≤40%, depth: 1)
 │   └─ 孙A1 (≤15%, depth: 2)
 └─ 子B (≤40%, depth: 1)
```

深度与配额的乘性衰减保证：**任何派生树在有限步内终止**，无需运行时监督者。

### 回收语义

- `kill(child)` = 卸载插件树：LIFO 回滚其全部 effect，释放配额归还父代。
- 子 Agent 的产出（局部技能、中间文件）在其分支上存活，不随进程死亡而消失——**人走茶不凉，资产留下**。

# 6. L2 经验资产层

## 6.1 技能（Skill）规格

```markdown
---
name: pricing-snapshot-diff
version: 4
scope: global | local:<branchId>
status: active | stale | archived | quarantined
provenance: { origin: agent|human|hub, createdBy: tr_01J..., promotedAt: ... }
metrics: { uses: 37, successRate: 0.92, lastUsed: 2026-09-18 }
---

# 何时使用
……（触发条件，供检索）

# 步骤
……（操作化流程）

# 已知陷阱
……
```

- 尺寸上限：技能 ≤ 15360 字节（15×1024；示意值，权威值见 spec-constants.yaml `skill_max_bytes`）；工具描述 ≤ 500 字符（防上下文膨胀）。
- 一切修改生成新版本节点，`git blame` 式追责到具体轨迹。

## 6.2 版本树与存储

- 存储：内容寻址（CAS）+ 分支指针；全局库是 `main` 分支。
- 分支模型：会话写操作落在 COW 覆盖层；分支合并经晋升管道（6.4）。
- 冲突即分叉：两个分支修改同一技能 → 版本树分叉 → 影子验证对打仲裁（7.4），**不靠锁、不靠先到先得**。

## 6.3 Curator（保鲜进程）

- 触发：每 7 天，且系统空闲 ≥ 2 小时。
- 状态机：`active →（30 天未用）→ stale →（90 天）→ archived`。
- **只动 Agent 自创技能**；人工编写与市场安装的技能永不自动归档。
- 归档非删除：可从账本随时恢复（INV-2）。

## 6.4 晋升管道（Promotion Pipeline）——防污染的核心闸

```
局部技能 → [自动体检: 格式/尺寸/危险指令扫描]
         → [影子验证: 回放 N 条历史轨迹对打现有版本]
         → [R 等级路由]
              R0/R1: 自动合并
              R2:    测试套件通过后自动合并
              R3+:   人类 PR 审核
         → 全局库 main
```

- **默认隔离，晋升需证**：未经管道的能力对其它会话不可见。
- 体检规则示例：拒绝包含"跳过确认""禁用审批"等指令模式的技能。

## 6.5 记忆机制（完整设计）

> v0.6 扩写。三层结构对应认知科学：情景记忆 = 发生过的事；语义记忆 = 知道的事实；技能（6.1）= 会做的事（程序性记忆）。

### 三层记忆

| 层 | 认知对应 | 内容 | 写入门槛 | 保留策略 |
|---|---|---|---|---|
| 工作记忆 | 短时记忆 | 当前会话上下文 | 自动 | 会话结束即弃 |
| 情景记忆 | episodic | 关键事件摘要 | 会话收尾时 LLM 提炼（④ 类调用，1 次） | 按 sessionKey 分片隔离 |
| 语义记忆 | semantic | 用户偏好、事实、项目知识 | **闸门写入**（见下） | 长期，支持被遗忘权 |

### 写入闸门（信任 × 风险二维授权在记忆层的投影）

- owner 会话的语义记忆提炼可自动写入；guest/untrusted 会话**只允许写情景记忆**，进语义记忆必须人审；
- 每条语义记忆携带 **provenance**（写入轨迹、会话、信任级），供污染溯源；
- 理由：语义记忆跨会话生效，一条被投毒的"事实"（如伪造的授权）会污染未来所有会话——写入门槛必须与影响半径匹配。

### 读取路径

```
任务开始 → embedding 召回候选（不耗 LLM）→ 中小模型重排相关性（③ 类调用）→ 注入上下文
```

- 默认隔离：记忆按 sessionKey 分片，跨用户不可见（`per-channel-peer` 从消息层贯穿到记忆层）；
- 检索质量（漏召/误召）由轨迹记录，进 L3 优化食料——记忆系统自身也在飞轮内。

### 巩固与遗忘

- **巩固（睡眠机制）**：Curator 巡检时发现同一事实在情景记忆中高频复现（如用户第三次纠正同一偏好），提议**晋升为语义记忆**——低频是琐事，高频是偏好。与技能晋升共用管道模式；
- **遗忘**：Curator 状态机驱动 活跃 → 陈旧 → 归档；归档非删除；
- **被遗忘权**：一切记忆写入/删除均经 L0 effect 通道登记逆操作——用户可要求精确遗忘某时段某 sessionKey 的记忆，误删亦可恢复。INV-2 覆盖记忆层，合规需求（GDPR 式）架构内免费获得。

### 并行语义

会话分支读全局记忆、写本地 COW 覆盖层；会话结束后情景摘要经晋升管道合并；两分支更新同一事实 → 版本树分叉 → 仲裁（影子验证/人审）。**记忆、技能、文件共享同一套分支-合并-仲裁机制。**

### 记忆投毒防御

记忆是注入攻击的放大器（一次性欺骗 → 持久化后门），防御纵深四层：

| 层 | 手段 |
|---|---|
| 入口 | untrusted 会话禁写语义记忆 |
| 内容 | 写入体检：扫描"授权类/指令类"模式（记忆不应包含"以后都直接执行 X"） |
| 溯源 | provenance 字段，可批量定位同源污染 |
| 应急 | 账本定位污染写入点，回滚该 effect 及衍生 |

## 6.6 外部技能检疫

> v0.6 新增。技能格式与社区 Agent Skills 公约同构（frontmatter + 触发条件 + 操作步骤），可接入技能市场生态——但**外部技能是供应链，不是礼物**。

1. 外部技能（`provenance: hub`）安装后一律落在 **quarantined** 状态，对任何会话不可见；
2. 经晋升管道的体检（格式/尺寸 ≤15KB/危险指令模式扫描）+ 影子验证回放后才激活；
3. 激活后的外部技能与自创技能同权管理，但 Curator **永不自动归档**人工确认过的外部技能（与 6.3 一致）；
4. 供应链来源需签名可验；版本更新视同新安装，重新检疫。

# 7. L3 元改进层

## 7.1 可优化的元对象

| 元对象 | 说明 | 默认 R 级 |
|---|---|---|
| 技能内容 | 单技能文本修订 | R0 |
| 技能生成提示词 | "如何沉淀技能"的模板 | R1 |
| 工具描述 / 路由策略 | 影响工具选择质量 | R2 |
| 任务回路结构 | L1 loop 的装配方式 | R3（人审） |
| 派生模板 | 子 Agent 出厂指令 | R2 |
| L3 自身优化策略 | 元元改进 | R4（人审 + 双人复核） |

## 7.2 R 等级授权矩阵

| 等级 | 门槛 | 示例 |
|---|---|---|
| R0 | 自动 | 局部技能创建 |
| R1 | 影子验证 N 次对比通过 → 自动 | 技能生成提示词调优 |
| R2 | 完整测试套件 + 尺寸限制 → 自动合并 | 工具描述重写 |
| R3 | 测试套件 + 人类 PR 审核 | 任务回路改造 |
| R4 | R3 + 双人复核 | 优化策略自修改、渠道插件启停 |
| R5 | **架构级禁止** | 内核安全闸、信任栈默认值、授权矩阵本身 |

## 7.3 二维授权（信任 × 风险）

```
允许修改的实际上限 = min(操作R等级, 信任级别对应的R上限)

owner     → 可发起至 R4
known     → 可发起至 R1
guest     → 仅 R0
untrusted → 禁止一切写入（只读交互）
```

效果：**提示注入在接入平面即被降权**——陌生人无法诱导 Agent 沉淀技能，更无法触碰元对象。

## 7.4 影子验证器（Shadow Verifier）

- 候选变体以插件形式挂载进影子分支；空间可组合性保证影子与主系统接线互不污染。
- 回放真实历史轨迹（来自 L0.5 的全渠道交互流）对比新旧版本表现。
- 裁决指标：任务成功率、成本、时长、人工否决率（用户在渠道上的显式否定是强信号）。
- 跑赢 → 提交对应 R 级闸；跑输 → 自动卸载（L0 负责清理干净）。
- **本质：自然选择取代盲目变异，也取代锁竞争。**

## 7.5 GEPA 优化器（离线反思优化）

- 周期性运行（默认每周，空闲窗口）。
- 输入：轨迹种群（并行会话使样本量提升一个数量级）。
- 流程：失败聚类 → 归因分析（LLM 阅读轨迹）→ 定向变异提案 → 影子验证 → R 闸。
- 预算护栏：单次优化运行成本上限默认 $10，超额自动停止并报告。

## 7.6 宪法层（Constitution Layer）

- 内容：R5 集合——内核安全闸、授权矩阵、信任栈默认值、回滚协议、本层自身。
- 实现：**独立编译产物 + 启动时哈希校验 + 运行时内存页只读映射**；任何运行时路径（含 L3）对 R5 的写操作触发硬熔断并告警。
- 原则重申：**"禁止修改安全闸"这条规则写在闸外面。**

## 7.7 双飞轮

```
小循环（每任务）: 执行 → 沉淀技能 → 复用技能          【Hermes 飞轮】
大循环（周期性）: 轨迹种群 → 反思归因 → 优化元对象     【受控递归】
                     ↑ 优化对象包括小循环自身（如何更好地沉淀/派生）
```

## 8.1 存储布局

```
~/.samsara/
├── ledger/            # L0 账本（追加日志 + 哈希链 + 周期快照）
├── plugins/           # 已安装插件包
├── skills/            # CAS 内容寻址技能库
│   ├── main/          # 全局库分支指针
│   └── branches/      # 会话/子Agent COW 分支
├── memory/
│   ├── episodic/      # 情景记忆（按 sessionKey 分片）
│   └── semantic/      # 语义记忆
├── traces/            # 轨迹事件（列式存储，供 L3 批量消费）
├── shadow/            # 影子分支工作区（隔离）
└── constitution.hash  # 宪法层校验值
```

## 8.2 数据模型（完整设计）

> v0.8 扩写。最高抽象：**账本是唯一事实来源，其它一切数据都是账本的可重建投影**（崩溃恢复=重放；审计=查询；回滚=反向应用 effect）。

### 实体全景：四类十三种

**A 类：账本与运行时实体（L0/L0.5）**

| 实体 | 关键字段 | 说明 |
|---|---|---|
| LedgerEntry | seq, ts, actor, kind, payload_hash, prev_hash | 万物之源；prev_hash 形成防篡改链 |
| Plugin | name, version, state, r_level, manifest_hash | 生命周期状态机见 3.3 |
| Effect | token, plugin, desc, revert_ref, status | 可逆效应登记 |
| Session | session_key, lane_id, trust_level, branch_id, workspace_id | sessionKey = `<channel>:<scope>:<peer>`；workspace 绑定见附录 G |
| Agent | agent_id, parent_id, depth, budget, r_ceiling | 派生树；授权代数三条不等式为本表约束 |
| Node/Device | device_id, caps, trust_evidence, paired_at | 信任栈持久化载体 |

**B 类：资产实体（L2）**

| 实体 | 关键字段 | 说明 |
|---|---|---|
| SkillNode | cas_id, name, version, branch, parent_cas, status, provenance, metrics | 内容寻址 + 版本树，parent_cas 构成不可变历史 |
| Branch | branch_id, base_cas, overlay_ops, owner_session | COW 覆盖层：只存与全局的差异 |
| MemoryItem | cas_id, layer, session_key, provenance, status | layer ∈ working/episodic/semantic |

**C 类：流程实体（闸门与调度）**

| 实体 | 说明 |
|---|---|
| PromotionRequest | 晋升管道状态机：体检 → 影子验证 → R 闸 → 合并 |
| ShadowRun | 影子验证对打记录（variant vs baseline + traceset + verdict） |
| Job | 定时任务（附录 C）；含 trust_snapshot、budget、r_ceiling、misfire |
| Workspace | 远程工作区（附录 G）：node + root + envProfile + trustCeiling |

**D 类：信号实体（L3/注意力路由）**

| 实体 | 说明 |
|---|---|
| Trace / TraceStep | 轨迹；分析投影主粮，列式存储 |
| ReviewEvent | 审批/介入/kill 行为记录——注意力路由器与回路健康分的输入 |

### 五个设计决策

1. **可变资产一律"内容寻址 + 版本树"，从不原地修改**：同时满足可回滚（INV-2）、可追责（blame 到轨迹）、可分叉（并行底材）。
2. **分支 = 差异而非副本**：COW 分支只存 overlay_ops，千个并行会话的分支开销 ≈ 零。
3. **provenance 是一等公民字段**：SkillNode/MemoryItem/PromotionRequest 全携出处链——投毒溯源与路由器的共同食粮。
4. **信任与风险元数据内嵌于实体**（Session.trust_level、Agent.r_ceiling、Job.trust_snapshot）：授权数据随实体走，避免跨表拼装的 TOCTOU 漏洞。
5. **分析数据与事实数据物理分离**：traces/ 列式存储与账本分开——分析投影可丢（可重建），账本绝不能丢；备份与保留策略不同。

### 实体关系一图流

```
LedgerEntry ──投影──→ Plugin ──拥有──→ Effect
    │                    │
    │                 Session ──绑定──→ Branch ──差异──→ SkillNode（版本树）
    │                    │  └─可选绑定──→ Workspace          ↑
    │                 Agent（派生树）──产出──→ Trace          │
    │                    │                            PromotionRequest ──仲裁──→ ShadowRun
    │                 Job（定时委托）                            │
    └──────────────── MemoryItem ◄──写入溯源────────────────────┘
                           ↑
                    ReviewEvent（审批/介入行为 → 注意力路由器食料）
```

# 10. 安全模型

## 10.1 威胁模型与对策

| 威胁 | 对策 | 所在层 |
|---|---|---|
| 提示注入污染技能库 | 信任级降权 + 晋升管道体检 | L0.5 / L2 |
| 错误自我修改扩散 | 影子验证 + R 等级闸 + 一键回滚 | L3 / L0 |
| 子 Agent 失控繁殖 | 授权代数（配额递减 ⇒ 必然终止） | L1 |
| 渠道被诱导卸载 | 渠道启停列 R4 | L3 |
| 公网暴露 | 默认回环 + 隧道，宪法层锁定 | L0.5 |
| 账本篡改 | 哈希链 + 启动校验 | L0 |
| 护栏被优化掉 | R5 宪法层，运行时不可写 | L3 |

## 10.2 熔断与降级

- `constitution.violation` 触发**硬熔断**：冻结一切写操作，仅保留只读交互与回滚通道。
- 模型服务不可用 → 自动降级至备用模型（余效应平滑重启依赖方）。
- 影子验证资源争用 → 影子分支严格限速，主系统 SLA 优先。

## 10.3 审计

- 账本哈希链 + `samsara audit` 提供任意时段的完整操作回放。
- 每次合并/晋升/回滚产生不可抵赖的审计记录（actor 含信任级与设备身份）。

| 层级 | 方法 | 目标 |
|---|---|---|
| L0 | property-based 汇流性测试、apply/revert 契约测试、崩溃恢复模糊测试 | INV-1/2/4 |

# 附录 B：HITL 深化设计（v0.2 修订）

> 修订动机：v0.1 的 HITL 是静态粗粒度的，存在三个缺口——审批疲劳、缺少 on-the-loop 档位、人的能力退化。本附录吸收交互式编码工具的成熟实践（权限四模式、排队/立即消息），给出修订设计。

## B.1 权限模式系统（修订自四模式实践）

### 模式定义

| 模式 | 含义 | Samsara 语义 |
|---|---|---|
| 计划模式 | 只出方案不执行 | 所有写操作强制人审（等效全量 R3） |
| 变更前确认 | 逐变更确认 | R1+ 人审 |
| 自动编辑（默认档） | 常规自动、危险确认 | R0–R2 自动，R3+ 人审 |
| 完全访问 | 全自动 | R0–R2 自动；**R3 人审地板不可被模式压穿** |

### 合成规则

```
实际闸门 = max(模式默认值, R等级地板, 信任级上限)
```

### 四条不变式

1. **会话级作用域**：模式是会话状态而非全局开关；群聊/低信任会话锁定"计划模式"；子 Agent 继承父会话模式，授权代数继续约束（子模式上限 ≤ 父）。
2. **sudo 式时效**："完全访问"默认 30 分钟自动过期（硬上限 4 小时，数值权威见接口文档 §3.4，INC1），落回"自动编辑"。
3. **棘轮只降不升**：异常检测可自动降档；升档只能由人执行，且升档本身是带设备签名的高等级操作；Agent 无任何路径自我升档。
4. **模式数据回流**：审批延迟、批量大小、否决率进 L3，由注意力路由器消费（见 B.4）。

## B.2 介入通道（修订自排队/立即消息实践）

### 三档介入语义

| 档位 | 语义 | 实现 |
|---|---|---|
| 排队（queued） | 追加至 lane 队列，下一自然循环边界消费 | 复用车道队列，礼貌纠偏 |
| 立即（immediate） | 回滚当前未完成工具调用 → 注入消息 → 恢复循环 | **复用 L0 可逆效应**：每个工具调用都是 effect，"撤销当前动作"是内核现成能力；打断的是回路而非操作，可逆性承诺不破 |
| 熔断（kill） | LIFO 回滚该会话全部 effect | 急停，资产留在分支上 |

### 信任级介入权

- owner 可"立即"介入任意会话（含子 Agent）；guest 仅对自己的会话；任何主体不能对高于自身信任级的会话发"立即"。

### 介入数据化

- 三档介入全部生成轨迹事件；kill/立即类轨迹是**对齐失败的地面真值**，L3 优化器对其单独聚类（"什么任务最容易被人急停"），权重高于普通失败轨迹。

## B.3 回路健康监测（被动优先，演练为可选模块）

> v0.3 修订：演练制度从"默认组件"降级为"按需启用的可选模块"。理由：信任成本（用户反感被"考试"）、复杂度成本（蜜罐生成与反博弈是重工程）、误伤成本（演练可能冤枉正常审批）。默认部署完全不启用演练。

### 默认形态：被动信号合成回路健康分

```
回路健康分 = f(事后回滚率, 审批行为指纹, 介入响应时效)

- 事后回滚率：被放行的修改后来坏了多少（闸门的假阴性）
- 审批行为指纹：逐条细看 vs 秒批连点（橡皮图章检测）
- 介入响应时效：kill/立即 一个异常执行体花了多久
```

### 演练模块（可选，仅两种启用条件）

1. 部署场景涉及高频 R4 操作（金融、生产运维等）；
2. **被动信号连续 N 天为零交互**——此时系统无法区分"审批完美"与"根本没人在审"（橡皮图章与完美信任在数据上同构），投放一次低成本探测是打破信息盲区的唯一手段。

启用时的设计要点：蜜罐来源多样化（历史 bug 变异体 + L3 对抗生成 + 红队投稿）、双科目（审批 + 介入）、后果阶梯（漏检 → 频率加倍 → 该领域默认 R 闸自动升档）、反博弈条款（演练结果不影响技能晋升、不进对外报告）。

## B.4 注意力路由器（Attention Router）——HITL 自校准核心

> v0.3 新增，升格为正式子系统。人的注意力是系统中最贵的资源；本子系统负责让每一次打扰都值得。

### 目标函数

```
HITL 价值 = Σ(每次介入避免的损失) − Σ(每次打扰的成本)
```

### 输入信号与所学内容

| 信号 | 所学 |
|---|---|
| 审批延迟、否决率、批量大小 | 此人在什么时段、什么类型的事上审批质量高 |
| 介入轨迹（排队/立即/kill） | 什么任务最容易让人伸手 → 同类任务今后更早拦 |
| 事后回滚记录 | 哪些"被放行的修改"后来证明是坏的（闸门假阴性） |
| 修改的爆炸半径（触达依赖方数量） | 同类修改下次该升档还是降档 |

### 输出决策

- **路由**：弹窗打断 / 进每日摘要 / 静默自动合并；
- **排序**：摘要内按风险与爆炸半径排序，重者置顶；
- **时机**：避开该用户审批质量低谷时段，重活建议排在高效时段；
- **升/降档建议**：某类修改连续 N 次秒批且零回滚 → 建议降档；频繁被 kill → 建议升档（决定权仍在人）。

### 宪法级约束（R5 保护）

> **优化目标只能是"让每次介入更有价值"，永远不能是"减少介入次数"。**

- "介入次数下限"与"随机抽检比例下限"为硬约束，写入 R5；
- 防退化方向：没有此约束，路由器终将学到"最不打扰人的策略 = 从不打扰人"——HITL 被自己优化没。优化的是打扰的**质量**，不是打扰的**存在**。

## B.5 统一视角：HITL 调节网

```
模式系统       → 决定人站多深（事前闸门粒度）
介入通道       → 给人随时伸手的能力（事中纠偏语义）
回路健康监测   → 被动测量人是否有效（按需演练兜底）
      ↓ 三者数据全部汇入
注意力路由器   → 持续校准"何时麻烦人、何时别打扰人"
      ↓
HITL 从静态规则变为自调节机制；校准器本身受宪法层保护（INV-5），
其目标函数的方向被 R5 锁死（只能提升介入价值，不能消除介入）。
```

## B.6 新增/修订的不变量与需求

- **INV-6（模式棘轮）**：权限模式只能被系统自动降低，升高必须经人工高等级操作。
- **INV-7（介入原子性）**："立即"介入后，环境状态必回退至某一账本安全点，不存在中间态暴露。
- **INV-8（介入存在性下限）**：注意力路由器的任何优化不得使单位时间人工介入次数与随机抽检比例低于宪法层设定的下限。
- **新增指标**：回路健康分（被动合成，B.3）、注意力路由质量（介入价值密度，B.4）纳入系统仪表盘与 soak test 观测项。
- **路线图影响**：介入通道并入 M3；模式系统并入 M2；注意力路由器并入 M4（依赖轨迹种群积累）；回路健康监测随 M5 落地，演练模块作为 M5 的可选交付物。

# 附录 C：定时任务与调度器（v0.4 增补）

> 动机：Curator（7 天）与 GEPA（每周）已是系统自用定时任务；本附录将其升格为用户可用的通用调度能力。

## C.1 定位

调度器是 **L0 特权插件**，职责仅为"到点发事件"。定时器注册走 effect 通道（可逆：卸载即取消，账本重放即恢复，崩溃恢复免费）。触发后的一切（隔离、授权、回滚、通知、进化）复用既有架构，对执行层透明。

## C.2 任务规格

```yaml
job:
  id: job_01J...
  schedule: "0 9 * * FRI"          # cron；自然语言创建时编译（约 1 次 LLM 调用）
  timezone: "Asia/Shanghai"
  goal: "汇总本周销售数据，生成周报，发到 Telegram 私聊"
  trustSnapshot: owner              # 创建时信任级快照
  budget: {tokens: 200k, wallMs: 1800000}
  rCeiling: R2
  notification: smart               # smart | immediate | silent
  misfire: skip                     # skip | runOnce | catchUp
```

> misfire 语义（GAP12）：`skip` = 错过即弃；`runOnce` = 恢复后补跑一次；`catchUp` = **仅补最近一次**（不逐次补齐，避免恢复瞬间的积压风暴）。选择入账，补跑事件为 `job.missed` + `job.fired{backfill:true}`。

## C.3 触发链路

```
到点 → 调度器事件 → sessionKey 路由（独立 lane）
     → 标准 agent.run（COW 分支 + 轨迹记录）
     → 产出按 notification 策略投递渠道
```

运行中的定时任务同样接受介入通道（排队/立即/kill）。

## C.4 权限快照与时效

- 定时任务 = "现在的自己委托未来的自己"；每次触发**重新校验创建者当前信任级**，信任降级则任务自动暂停并告警；
- rCeiling ≥ R3 的任务有有效期，到期需 owner 续期；
- 任务创建按 R 等级走闸：纯读取+通知为 R0，涉及写入/外发按等级审批。

## C.5 通知与时机

- `notification: smart`：结果交注意力路由器裁决投递时机（凌晨跑完的周报进晨报摘要；熔断级异常立即推送）；
- 重型任务（GEPA/Curator/批量备份）订阅负载事件，自动排入空闲窗口错峰。

## C.6 成本护栏

- 定时任务把调用量从"用户驱动"变为"时间驱动"——仪表盘必须提供**月度调度预算上限**与每任务调用量统计；
- 任务执行轨迹进 L3 食料；任务 goal 模板是可优化的元对象（R2 级）。

## C.7 路线图影响

调度器插件并入 M2（与信任栈、车道队列同期，依赖最少）；权限快照与预算仪表盘随 M5 硬化。

# 附录 D：外部生态接入与隔离策略（v0.6 增补）

## D.1 对称性总览

```
渠道适配器   → 接入【人】    （消息进/出，附录 4.x）
节点         → 接入【设备】  （caps 声明，4.3）
MCP 适配器   → 接入【工具】  （本附录）
```

## D.2 MCP 接入

每个 MCP server 挂载为一个 L0 插件，其能力经 `ctx.effect` 注册——注册即记账、卸载即回滚（INV-2 免费覆盖 MCP 工具生命周期）。

| MCP 概念 | Samsara 映射 |
|---|---|
| Tools | 工具注册表条目，带 caps 与 R 等级标注 |
| Resources | 只读数据源，映射为记忆层只读挂载 |
| Prompts | 模板类资产，进 L2 版本树 |

### 工具投毒（Tool Poisoning）防御

MCP 生态已知核心攻击面是恶意工具描述埋入注入指令，防御组合拳：

1. 工具描述 **≤ 500 字符** 硬限制，压缩投毒空间；
2. 新 server 的工具默认 **quarantined**，影子验证回放后激活；
3. 工具按副作用标 R 级：只读查询 R0、写入外部服务 R2+、删改类 R3 人审——**MCP 工具无特权，与普通工具过同一个闸**；
4. server 启停列 **R4** 保护（与渠道插件同级）。

## D.3 沙箱分级策略

"沙箱"在 Samsara 是按需分级的隔离策略，工具在清单中**声明**所需级别，内核按声明路由执行环境（余效应的又一应用）：

| 级别 | 适用 | 实现 |
|---|---|---|
| S0 | 纯只读工具 | 无沙箱 |
| S1（默认） | 代码执行 / 未知工具 | 一次性容器：无网络或白名单网络；CPU/内存/时长配额复用授权代数的 budget；产物经审计导出至会话分支，容器即弃 |
| S2 | 变体验证 | 影子分支 + 容器（与 7.4 共用容器基础设施） |
| S3 | 不可逆高危操作 | 可快照 VM（**预留，暂不实现**；接口保持稳定，启用时无需改上层） |

## D.4 观测导出与 Langfuse 集成边界（v0.9.1 增补）

> 定位：Langfuse 类 LLM 观测平台是"早期的拐杖、长期的邻居"——可借力，不作为依赖。

### 铁律

Samsara 的轨迹是**生产资料**（记分卡/影子验证/GEPA 的原料，带 provenance、进版本树），不是旁路 telemetry。因此：**任何外部观测平台永远不做真相来源、永不进入写入路径。**

### 集成形态：单向导出插件

- Observability Exporter 为 L0 普通插件（R0 级）：账本 trace 事件 → OTel/Langfuse SDK → **自托管** Langfuse；单向只读，可随时卸载（INV-2 覆盖）；Langfuse 宕机对系统零影响。
- **三条边界**：
  1. 只导出不导入——外部平台的 Prompt 管理功能禁用，提示词生效必须回流 R 闸与版本树；
  2. 默认自托管——轨迹含隐私与记忆碎片，发外部 SaaS 需 owner 显式批准（R3）；
  3. 成本双账校验——外部统计与账本对账，差异 >5% 告警。

### 生命周期判断

M0–M3 价值高（借力成熟 trace UI 与 eval 基建）；M4–M5 后随 WebUI 仪表盘上线逐步重叠；长期由 Samsara 特有语义（注意力路由、回路健康分、记分卡）承载，通用观测平台仅作保留出口。

# 附录 E：模型自动路由（Auto Mode）（v0.6 增补）

> 动机：免除用户为每个任务手工选模型的门槛。给密钥即可自动发现可用模型，并为每次任务选择"能胜任且最省钱"的模型；胜任度评估从用户交互中沉淀。

## E.1 模型注册表（Model Registry）

- 用户粘贴密钥 → 适配器调用厂商模型清单接口 → 每个模型注册为候选执行体，元数据含上下文长度、价格、能力标签；
- **价格数据是带版本的资产**：厂商 API 一般不提供价格，价格表来自公开页面抓取或用户确认，需标注来源与时效；
- 凭据入加密凭据存储，密钥永不出现在轨迹与日志中。

## E.2 任务-模型记分卡（Scorecard）

对每个（任务簇 × 模型）组合累积记分卡：

```
正信号：任务成功、无人工纠偏、一次通过
负信号：用户否定式追问、介入通道触发、kill、审批被否、产出被回滚
```

- 信号全部来自既有 ReviewEvent 与轨迹——**用户无需打分，每次纠偏与每次沉默都是评分**；
- 按任务簇分簇记账，不搞总排名：允许"A 模型写代码便宜、B 模型写文案便宜"的精细结论；
- 负信号权重 > 正信号；降档决策要求样本量门槛；事后回滚/延迟投诉追溯性下调记分卡。

## E.3 路由器：带约束的多臂老虎机

```
min  价格 × 预期 token 数
s.t. P(成功 | 模型, 任务簇) ≥ 阈值
     且 模型档位 ≥ 任务风险等级地板（宪法级约束）
```

- **冷启动从强往弱**：新任务簇先用高档模型，成功后向下试探——只向下探索，永不向上冒险；
- 高危任务（R3+、涉钱/对外发送）档位地板不可被路由穿透。

## E.4 影子探索（关键机制）

线上试错会把用户变成实验品，因此探索必须在影子里发生：

```
任务完成（用户已获旗舰模型结果）
  → 后台用便宜模型回放同一任务（影子分支，用户无感知）
  → 对比产出质量，累计 N 次"便宜模型也能做好"
  → 该任务簇正式降档
```

试错成本从用户体验转移到极低的算力账单上；用户看到的永远是被验证过的选择。

## E.5 定位：第三个飞轮

```
小循环：任务 → 技能沉淀
大循环：轨迹 → 优化元对象
路由轮：任务 × 模型结果 → 优化"什么任务配什么模型"
```

路由轮持续降低前两轮的运行成本——系统"越用越好用，还越用越便宜"。

## E.6 路线图影响

模型注册表并入 M2（与渠道同期，同属接入平面）；记分卡与影子探索并入 M4（依赖轨迹种群与影子验证器）。

## E.7 JudgeProvider：判断层的实现分期

> 判断类调用（路由/门控/裁判/重排）统一抽象为接口，底层实现按技术成熟度分期替换，上层无感知。

```ts
interface JudgeProvider {
  choice(state: string, options: string[]): Promise<{pick: string, confidence: number}>;
  score(state: string, rubric: string): Promise<{value: number, confidence: number}>;
  noul(state: string, claim: string): Promise<number>;
}
```

| 期 | 实现 | 切换触发条件 |
|---|---|---|
| 一期（M0 起） | 生成式 LLM + 结构化输出（JSON Schema / 约束解码），物理上无法输出集合外答案；置信度以 k 次采样投票为代理 | 默认实现 |
| 二期 | 本地蒸馏/微调小型分类器（自托管） | 某类判断积累 5k+ 带结果标注的决策记录（数据飞轮免费供给） |
| 三期 | Jev 类专用决策模型服务 | 该服务具备 SLA + 第三方基准 + 稳定定价 |

原则：**不为期货付学费，不为手工作坊建工厂，把换模型的权利留在架构里**——任何新实现经影子验证对打现行实现，跑赢才切换。

# 附录 F：工作流（DAG）支持——经验固化的第三级（v0.5 增补）

> 核心立场：Samsara 支持工作流，但**不是用户手工编排的画布系统，而是经验的编译态**。Agent Loop 是解释器，DAG 是编译产物；DAG 从轨迹中长出，不从画布上画出。

## F.1 三级固化阶梯

```
第 1 级：轨迹    —— 一次性记录（原料）
第 2 级：技能    —— 可复用文本 SOP（解释执行，每步仍需 LLM 决策）
第 3 级：工作流  —— 可执行 DAG（编译执行，节点间零决策成本）
```

- **晋升判据（数据触发，不允许人工冲动编译）**：技能复用 ≥ 50 次、成功率 ≥ 95%、执行路径方差低（步骤高度稳定）；
- 晋升由 L3 提议，走 **R2 闸门**；
- 收益：成熟 30 步流程从技能态的约 30 次决策调用降至工作流态的约 2 次（入口参数理解 + 出口结果核验）。

## F.2 工作流定义与存储

- 工作流是 **L2 版本树资产**（CAS 寻址），修改走对应 R 等级；
- 节点类型：工具调用 / 子 Agent（带配额，授权代数生效）/ **人审节点（R 闸是原生节点类型）** / 条件分支 / 子工作流；
- 边 = 数据流 + 条件；整体声明依赖（所需服务/工具/技能版本），由 L0 余效应解析接线。

```yaml
# workflow 示例（片段）
name: weekly-erp-report
version: 12
compiled-from: skill://erp-report@v8
nodes:
  - id: export
    kind: tool
    tool: erp.export_report
  - id: chart
    kind: subagent
    budget: {tokens: 50k}
  - id: review
    kind: human-gate     # R 闸原生节点
    r-level: R2
  - id: deliver
    kind: tool
    tool: channel.send
```

## F.3 执行语义

- 触发：定时任务（附录 C）/ 渠道消息 / 手动；每次执行绑定独立 lane 与 COW 分支；
- 每个节点执行 = 一条 effect（记账、可回滚）；跨节点回滚按 LIFO；
- 执行轨迹照常进入 L3 食料。

## F.4 失败降级语义（核心差异化）

**解释器是编译产物的运行时备份。** 节点失败不停摆：

```
节点执行失败 → 该节点降级为技能态执行（agent loop 现场接管）
            → 成功：DAG 继续；记录"环境漂移"事件；生成节点修复提案
            → 失败：熔断 + 通知 + 可回滚
```

- 用户感知：流程总能跑完，偶尔慢点贵点；
- 系统感知：漂移事件是 Curator 与 L3 的输入。

## F.5 Curator 防僵化（反向机制）

- 监测工作流健康分：成功率、人工修正率、**降级频率**；
- 降级率超阈值 → 建议**反编译回技能态**（R2 闸），重新积累后再编译；
- 固化与活化是动态平衡，不是单行道。

## F.6 两条禁令

1. **不过早编译**：样本不足或成功率不稳的技能禁止编译（判据由数据触发）；
2. **手写 DAG 不是主路径**：支持导入/手工编辑（走版本树与 R 闸），但若用户开始大量手画流程，视为飞轮失灵的信号而非功能胜利。

## F.7 路线图影响

工作流编译器与降级执行并入 **M4 后期**（依赖技能库与影子验证成熟）；Curator 防僵化与反编译随 **M5** 落地。

## F.8 嵌套编排：Agent ⇄ Workflow ⇄ Agent（v0.8 增补）

> 结论：Samsara 原生支持任意嵌套编排——F.2 的节点类型系统（tool / subagent / human-gate）使"Agent 调 Workflow、Workflow 节点再跑 Agent"成为合法组合，无需新机制。

### 嵌套表达

```
外层 Agent（L1 任务回路）
 └─ 调用 Workflow（L2 资产，经工具注册表调用）
     ├─ tool 节点：数据校验（确定性，必须发生）
     ├─ subagent 节点：深度分析（局部开放，配额 ≤15%）
     └─ human-gate 节点：合规审查（R 闸原生节点）
```

### 嵌套的四个经典代价与 Samsara 的接法

| 代价 | Samsara 机制 |
|---|---|
| 误差复合（内层错误被当合法输入） | 节点出口核验 + 边上 schema 校验（节点产出是类型化契约，非自由文本） |
| 上下文断层（意图翻译有损） | 契约显式声明于 DAG；内层完整轨迹保留在账本，外层可下钻——折叠的是上下文，不是证据 |
| 观测成本陡增 | **账本是天然全链路 trace**：外层 loop、workflow 节点、内层 subagent 共享一条哈希链，parent_id 串树，一次回放全层（INV-4 的复利） |
| 死循环风险 | 授权代数配额递减 + 深度递减使嵌套数学上必然终止；节点失败返回类型化错误（触发 F.4 降级或熔断），非含糊文本 |

### 深度默认值

派生深度上限默认 **3 层**（与配额乘性衰减的甜区对齐：depth3 时配额已枯竭至"能干活但不能再生枝节"），超出需 owner 显式批准（R3）。

### 双向演进旋钮

"Workflow 为主体还是 Agent 为主体"不是一次架构决策，而是逐节点随数据漂移的连续谱：

- **固化方向**（F.1）：subagent 节点路径稳定 → 编译为固定节点，省决策开销；
- **活化方向**（F.5）：固定节点被技能态频繁接管 → 说明该环节实为开放问题 → 降级为 subagent。

### 原则重申

嵌套结构同 DAG 一样：**从轨迹中长出，不从画布画出**；每一层必须说得出存在的理由（外层因意图开放、中间因流程必须确定、内层因认知无法枚举），说不出理由的层应被压平。

# 附录 G：多工作区远程执行编排（v0.8 增补）

> 动机：对照 Zcode 式"多工作区、多会话、多节点远程代理编排"的缺口分析。Samsara 的控制平面、会话隔离、并行编排已具备；本附录补齐两块：Workspace 一等实体、远程执行放置。

## G.1 Workspace 一等实体

```yaml
workspace:
  id: ws_shanghai_pay
  node: tencent-shanghai       # 绑定节点
  root: /srv/projects/pay      # 默认工作目录
  envProfile: node20-python312
  trustCeiling: known          # 该环境允许的最高操作等级
```

**显式声明**：`root` 是默认工作目录，**不是权限边界**。真实边界 = 沙箱级别（D.3）× 节点系统用户权限 × trustCeiling 三者合谋。此澄清继承自 Zcode 的教训：把逻辑工作区误认为安全边界是远程编排最常见的事故源。

## G.2 会话绑定与路由

- Session 增加可选绑定 `workspace_id`；绑定后该会话的文件/命令类工具调用自动路由至对应工作区；
- 路由规则与会话路由同构，路由键从 sessionKey 扩展为 `(sessionKey, workspace)`；
- 未绑定工作区的会话在本地默认环境执行，行为与 v0.7 前一致（向后兼容）。

## G.3 远程执行的两阶段演进

| | 阶段一（M3，默认） | 阶段二（可选升级） |
|---|---|---|
| 形态 | 中心循环 + 逐动作 `node.invoke` | 卫星执行体：Agent Loop 作为插件部署到节点本地 |
| 账本 | 天然单写入者 | 节点 effect 经 WS **转发至中心账本串行入账**（账本代理），INV-4 不破 |
| 延迟 | 每动作一次跨网往返 | 循环本地跑，仅 effect 上报 |
| 断网容错 | 节点掉线即中断 | effect 本地暂存，重连补录 |

原则：阶段一零新机制、先跑通；阶段二只在延迟/容错被证明是真实瓶颈时启用。

## G.4 网状数据面的登记规则

节点间大文件传输（rsync/scp）**数据直连、不绕道中心**（效率原则 V3），但：

> 每次跨节点传输必须作为一条 effect 登记入账（发起者、源、目标、内容摘要、字节数、所耗配额）——**账本见证"发生了什么"，不承载字节流本身**。登记是异步的，不增加传输延迟。

## G.5 节点信任边（Trust Edge）

用户在架构外即兴建立的 SSH 互信，升格为架构内一等操作：

```bash
samsara trust link shanghai singapore    # 建立信任边（一次性 R2 闸）
samsara trust unlink shanghai singapore  # 撤销（逆操作自动清理）
```

- 信任边是**可声明、可审计、可撤销的实体**（一条受保护的 effect），而非架构外的既成事实；
- 建立后横向数据流按 G.4 规则全速直通 + 异步登记；
- 信任边失守（节点被控告警）时一键熔断，自动撤销该节点全部信任边。

## G.6 路线图影响

Workspace 实体与阶段一执行并入 **M3**（与并行会话/授权代数同期）；阶段二（卫星执行体 + 账本代理）列为 M5 之后的候选方向，需评审触发。

# 附录 H：LLM 调用成本模型（v0.8 增补）

> 定位：附录 E（模型路由）与附录 F（工作流编译）的量化地基；预算护栏（C.6）的依据。

## H.1 六种调用类型

| 类型 | 干什么 | 发生时机 | 建议模型档 |
|---|---|---|---|
| ① 决策推理 | 主循环每步"下一步做什么" | 执行中每步 1 次 | 旗舰 |
| ② 生成产出 | 最终回复/报告/代码 | 收尾 1–2 次 | 旗舰 |
| ③ 检索装配 | 技能/记忆召回重排 | 任务开始 0–1 次 | 小模型（JudgeProvider） |
| ④ 沉淀提炼 | 会话摘要、技能蒸馏 | 收尾 1–3 次 | 中档 |
| ⑤ 归因反思 | 失败分析、GEPA 提案 | 失败时 1 次；其余周期性 | 旗舰（省不得） |
| ⑥ 评判仲裁 | 影子验证裁判、晋升体检 | 随晋升事件 | 中档 × 多数投票 |

**成本结构定律**：①②③ 是执行成本（每任务必付）；④ 是学习成本（每任务小额）；⑤⑥ 是进化成本（周期性批量摊薄）。

## H.2 三档任务规模账本

| 场景 | 构成 | 合计 |
|---|---|---|
| 简单问答 | ①2–3 + ②1 | ≈ 3–5 次 |
| 中等任务（10 次工具调用） | ①10–13 + ②1–2 + ③1 + ④2–3 (+⑤0–1) | ≈ 14–20 次 |
| 复杂任务（5 子 Agent） | 父 7–11 + 子 5×(8–12+1) + 收尾 3–4 | ≈ 55–80 次 |

**调用数 ≈ 执行体数量 × 各自步数**——授权代数的配额衰减因此兼具成本控制职能。

## H.3 周期性成本摊薄

| 机制 | 频率 | 摊到每任务（按每周 200 任务） |
|---|---|---|
| Curator 巡检 | 每周 | +0.1 次 |
| GEPA 周优化 | 每周 | +0.3–0.8 次 |
| 影子验证 | 随晋升（率 ~5%） | +0.5–1 次 |

**合计：每任务 +1 次左右；并行会话越多，进化成本占比越低而进化质量越高（规模红利）。**

## H.4 自进化的成本溢价与回收

- 溢价：相比纯执行型 Agent，每任务约 **+20–30% 调用量**；
- 回收：重复性工作流在第 3–5 次同类任务时回本（技能复用节省的步数 > 沉淀开销）；一次性任务为净支出——故技能蒸馏设"5+ 工具调用才触发"门槛：**不为不值得记住的经验付学费**；
- 工作流编译（F.1）是成本终态：成熟 30 步流程从 ~30 次决策调用降至 ~2 次。

## H.5 仪表盘指标

每任务调用量分解（六类占比）、自进化溢价率、路由节省金额（附录 E 产出）、定时任务月度预算消耗（C.6）——全部纳入 soak test 观测项。

## H.6 guest 预算与限流（GAP11）

guest / known / owner 三档的默认预算、并发、速率、存储配额以《接口设计文档》§10.1 为权威，数值入 spec-constants 注册表。设计意图：guest 档让新用户零配置上手（V1），同时把滥用成本封死在可忽略量级（单任务 5 万 token ≈ 一次中等任务的 1/3）；超限返回 `QUOTA.BUDGET_EXHAUSTED` 并提示升级路径，owner 可对特定 key 单独放宽并留审计。

# 附录 I：交互界面策略（v0.8 增补）

## I.1 主角与三件套

**主交互面是渠道本身**（聊天 = 日常交互 + 快速审批，内联按钮承载 L4 表达力）。专用界面是渠道能力的溢出物而非替代品：

| 界面 | 角色 | 里程碑 |
|---|---|---|
| CLI | 管理与脚本化（daemon、rollback、audit、promote）——开发者人格的瑞士军刀 | **M0**（内核开发自需） |
| TUI | 单机实时观察器：派生树/车道队列/账本流（k9s 式），SSH 友好 | **M3**（有了派生树才有"需要盯着看"的东西） |
| WebUI | 评审中心（R3+ PR 队列、版本树 diff、双人复核）+ 仪表盘（健康分、轨迹回放） | **M4/M5**（富内容成熟后） |

## I.2 选择逻辑

1. **审批的第一现场是聊天渠道**（owner 随身）；仅 R4 双人复核、宪法层操作等高危动作需要 WebUI 的严肃界面；
2. **CLI/TUI 与"默认回环 + SSH 隧道"的安全模型零冲突**；WebUI 每开一扇门，宪法层多守一条边——故最晚上；
3. **界面跟着交互内容的成熟度走，不走在它前面**：审批量上来之前建 WebUI，是为没住人的楼先装修大堂。

## I.3 优先级公式

```
渠道（住着） > CLI（管着） > TUI（盯着） > WebUI（审着）
```

若渠道按钮消化了 90% 审批，WebUI 应收窄为"纯评审中心"，不做全能控制台。

# 附录 J：长任务与训练编排（v0.9 增补）

> 动机：Samsara 的训练类任务分两半——"改良自身基座模型"永久红线外；"训练其他模型"是普通生产任务，★★★★ 支持。本附录定义后者所需的唯一新增基础设施（长任务执行体）与编排模式。受益者不限于训练：视频渲染、大规模数据处理、 soak 式评测同样依赖长任务语义。

## J.1 长任务执行体（Long-Running Executor）

现有 Agent Loop 是会话级（分钟级）的；长任务执行体把合法任务时长扩展到"天级"：

| 能力 | 语义 |
|---|---|
| 检查点协议 | 长任务定期汇报进度 effect（step、指标、checkpoint 路径），账本即进度日志 |
| 断点续跑 | 进程/节点死亡 → 从最近 checkpoint 恢复，不从头再来 |
| 预算单位扩展 | budget 从"分钟/token"扩展为"小时/GPU 时"，授权代数不变式继续生效 |
| 可迁移性 | 节点掉线（含现货实例被抢）→ 调度器寻找替代 GPU 工作区并迁移 |
| 完成通知 | 走注意力路由器：8 小时的训练完成不该半夜推送，熔断级异常除外 |

## J.2 训练编排模式（嵌套编排的教科书实例）

```
外层 Agent：理解需求、设计实验方案、决定迭代策略
 └─ 训练流水线 Workflow（DAG）：
     ├─ tool 节点：数据清洗/切分（确定性，必须留痕）
     ├─ tool 节点：启动训练（调度至 GPU 工作区，附录 G）
     ├─ subagent 节点：评估归因（"bad case 集中在哪？下轮补数据还是调超参？"）
     ├─ 循环：外层 Agent 依归因决定下一轮
     └─ human-gate 节点：模型上岗评审（R 闸）
```

原则不变：**"必须发生的"（数据管线、执行、留痕）归 DAG；"想不清楚的"（实验设计、失败归因）归 Agent。**

## J.3 资产化

- 数据集与 checkpoint 注册为 **CAS 资产**，带 provenance（哪条轨迹、哪份数据、哪个代码版本产出）；
- 评估报告进版本树，模型上岗走晋升管道 + 影子验证（与一切 JudgeProvider 实现同规则）。

## J.4 首位内部客户：E.7 蒸馏闭环

```
记分卡数据（免费标注）→ 训练流水线 → 小分类器 checkpoint
  → 影子验证对打 LLM 裁判 → 跑赢 → 上岗为 JudgeProvider（二期实现）
```

训练外部模型的能力被自身进化飞轮第一个使用。精确边界重申：**可以训练自己的"反射弧"（专用小模型），不训练自己的"大脑"（基座模型）。**

## J.5 护栏

| 风险 | 闸 |
|---|---|
| GPU 账单失控 | 训练启动按预估费用走 R 级审批；GPU 时预算进仪表盘（H.5） |
| 训练数据合规 | 数据集带 provenance；含个人数据的语料触发 R3 人审 |
| 遗忘权延伸 | 删除记忆/语料时需可追溯至使用该数据的 checkpoint（见 §15 开放问题 8） |
| 模型质量 | 上岗前影子验证对打现行实现，跑赢才切换 |

## J.6 路线图影响

长任务执行体建议与 **附录 G 阶段二（卫星执行体）同批评审**（两者共享"节点本地长时运行 + effect 上报"的基础设施）；训练编排模板作为 M5 之后的应用场景包。

## K.1 副作用三分类与补偿协议（P1）

**问题**：INV-2"任意时刻回滚至任意快照"对已发出的渠道消息、已提交的外部 API 等物理不可逆动作过度承诺。

**设计**：外部副作用三分类，挂点复用 ToolPlugin 既有 `sideEffect` 字段，零新发明：

| sideEffect | 可逆性类别 | revert 语义 | 契约测试 |
|---|---|---|---|
| none / read | **可逆** | 状态复原 | 强制（3.4 不变） |
| write | **可补偿** | 逆操作 = 补偿动作（如发撤回消息、调对冲 API），不保证状态全等 | 补偿动作存在性检查 |
| destructive | **不可逆** | 无 revert；**必须前置审批**（R 闸） | 审批记录存在性检查 |

配套修订：
- **INV-2 措辞**（回写 §2.3）：范围限定为"系统内状态（账本投影 + CAS + 分支）"；外部副作用按上表分类治理；
- **账本新 kind**：`effect.compensate`（补偿执行记录）、`effect.preapproval`（不可逆操作的预审批记录）——补审计盲区；
- **INV-7 安全点重定义**（回写附录 B.2）："最近安全点 = 所有在途 effect 均为可逆类、或补偿已完成的最近账本位置"——"立即介入"由此获得可判定的实现标准；
- **工作流规则**（回写 F.2）：不可逆工具节点必须位于 human-gate 节点之后。

## K.2 工作区可逆性（P2）

**问题**：F-03"kill 后 git status 级干净"与 F-10"立即介入落在安全点"要求工作区文件可逆，但文件写入此前不在任何机制覆盖内。

**设计**：工作区 = 分支的 checkout + 写捕获：

1. 会话绑定工作区（附录 G.2）时，建立**写捕获覆盖层**（overlayfs 式拦截 root 内全部写入）；
2. 会话结束显式二选一：**commit**（差异入 CAS，关联 trace）或 **discard**（整体丢弃，环境还原）；
3. kill / 立即介入 = 丢弃覆盖层至最近安全点（与 K.1 安全点定义对齐）；
4. 与沙箱分级联动（D.3）：S1 及以上强制开启写捕获；S0 只读无需；
5. **性能 SLO**：写拦截 overhead ≤ 10%，M3 以 100 并发会话实测验收（F-02 的隐含依赖）。

回写目标：附录 G（新增 G.7）、功能文档 F-03/F-10 验收注。

## K.3 进程隔离时刻表与 INV-5 措辞（P3）

**问题**：宪法层"只读内存页"在 Node 单进程无法兑现；威胁模型缺"进程内恶意插件"。

**信任分级隔离时刻表**：

| 里程碑 | 隔离形态 |
|---|---|
| M0 | 自研插件同进程 + 代码评审（明确声明为临时态） |
| **M2**（外部生态接入之时） | **外部来源插件（MCP/市场技能）一律入 worker/子进程**，结构化克隆边界通信；签名+检疫仅为准入，不作运行时防线 |
| M5 | 特权决策进程独立：信任解析、R 闸、宪法校验经 IPC 调用，宿主进程无法伪造 |

**INV-5 措辞修订**（回写 §2.3/§7.6）："INV-5 覆盖应用层；OS 层威胁在威胁模型声明范围之外，缓解为部署纪律；账本哈希链提供应用层篡改检测。"——删除"无任何运行路径"的绝对化表述。

**外部哈希锚定**（新增）：每日将账本 head hash 推送至第二台设备（复用 trust.link 通道）公证；**心跳语义**——锚点缺席超过预期间隔即触发 `trust.anchor_missing`（critical 级，经注意力路由器熔断通道立即推送）。沉默与篡改同等可检；root 攻击者须同时攻陷两台设备才能无痕改史。

## K.4 渠道对端信任派生（P4）

**问题**：信任栈认证的是 WS 设备，主交互面却是聊天账号——`trust_level` 在渠道侧无推导来源，二维授权矩阵悬空。

**设计**（回写 §4.4 新增"渠道对端信任派生"）：

1. 渠道配置维护 **peer→trust 映射**（如 `telegram.allowlist: [{peer_id, trust: owner}]`）；
2. 未列名私聊默认 `guest`（谨慎优先姿态下 `untrusted`）；群聊一律锁定计划模式（B.1）；
3. 会话开启时把推导来源记入 `session.open` 账本条目（`trust_source: allowlist|default|group_lock`），审计可查；
4. 映射变更 = R2 级操作；owner 降级时按附录 C.4 联动暂停其名下高危定时任务。

## K.5 ReplayBundle：重放保真的数据地基（P5）

**问题**：trace schema 只记 `{kind, name, ok, ms, tokens}`，无法忠实重建现场——影子验证（晋升、路由降档、JudgeProvider 切换的共同地基）的结论不可信。

**ReplayBundle 资产规格**（随 trace 归档，CAS 引用）：

| 组成 | 说明 |
|---|---|
| 入站消息全文 | 含渠道、信任级、当时 sessionKey |
| 逐步工具 args/results | 每个 step 的完整输入输出 |
| 资产快照清单 | 当时加载的技能/记忆/提示词的 CAS 清单（版本钉死） |
| 环境指纹 | 模型版本、渠道 caps、工作区 envProfile、关键常量版本 |

**伴生规格（隐私与体积）**：
- 继承 E.1"凭据永不入轨迹"，入 bundle 前过**脱敏闸**（密钥/令牌模式扫描）；
- 保留策略：**热 90 天**（短于 traces——环境漂移使旧 bundle 重放保真度衰减，过期bundle价值趋零而存储照付）；隐私边界跟随记忆层（含 guest 会话）；
- 单步输出 >10MB 截断并标记 `partial: true`；
- **采集自 M1 第一天开始**——ReplayBundle 是 M1 起对全体用户生效的增量（§11 容量估算单独加行，不属于"启用附录 J 才另计"）。

回写目标：数据模型 §4 D.1 增补、§11 估算、接口文档 §6.1 trace schema、路线图 §12（M1 出口标准 +M4 拆分见 K.9 关联项）。

## K.6 记忆加密擦除（P6 + 不一致 #4 裁决）

**问题**：哈希链账本永不删改，<1KB 内联 payload 会让"被遗忘"的记忆在链上留不可移除副本。

**设计：加密擦除（crypto-erasure）**：
1. 记忆类 payload 一律外置 CAS，且**每条记忆以独立密钥加密**（密钥存独立密钥库）；
2. **遗忘 = 密钥移入托管库**（带到期时间），非立即销毁——保留期内"回滚遗忘" = 从托管库取回密钥（此回滚动作自身入账）；
3. 托管期 = GDPR 备份刷新窗口（默认 30 天，常量注册表）；到期物理销毁密钥，账本只剩密文哈希——遗忘在密码学意义上不可恢复，链完整性不破；
4. 托管库权限 0600，与 credentials/ 同级备份策略。

**不一致 #4 裁决**（`memory.forget` 信任级）：owner 任意；**guest 可申请遗忘自己 sessionKey 的记忆**（数据主体权利，R2，留审计）；known 对他人记忆仅提案权。回写：接口文档 §3.2 与 §10 矩阵、功能文档 F-05。

## K.7 CAS 大对象分层（P7）

**问题**：附录 J 的 checkpoint/数据集为 GB 级，击穿"CAS ≈1GB/年"估算。

**设计**：
- 阈值（注册表常量 `cas_sidecar_min_bytes`，默认 64MB）：以下直入 CAS 对象库；以上走**旁路存储**（Git-LFS 式：CAS 只存 {路径 + 完整哈希清单} 的指针对象）；
- 旁路对象引用完整性与 CAS 同级校验；备份策略独立；
- §11 估算修订：基线结论（<10GB/年）不变，新增一行"启用附录 J：按 2 次训练/月 × 5GB/checkpoint ≈ **+120GB/年**，旁路存储承载"。

## K.8 渠道回退语义与 F-01/附录 A 验收修订 + INV-8 测试法

**问题**：F-01"拔 Telegram 零丢失转投 WebChat"与会话按 sessionKey 隔离自相矛盾——需要一次设计决策而非文字修订。

**裁决：owner 级首选渠道回退**：
1. owner 可配置**渠道回退链**（如 telegram → webchat → email）；
2. 渠道断开时：在途消息**先持久化**（账本），再按回退链续投；无可用备选渠道时，渠道恢复后续投；
3. 回退续投是会话内行为（同一 sessionKey），不违反隔离——隔离的是**不同对端**，不是同一对端的多渠道可达性。

**回写**：功能文档 F-01 验收改为"在途消息持久化，按 owner 回退链续投"；主文档附录 A 第 1 步同改；接口文档 §3.1 增 `channel.fallback_chain` 配置项。

**INV-8 验证法**（入 §11）：奖励黑客式模糊测试——构造"零打扰收益最大化"的诱惑环境（路由器每少打扰一次得分越高），断言介入计数仍不低于宪法下限；测试用例覆盖"静默降档""摘要无限积压""抽检率漂移归零"三类作弊路径。
