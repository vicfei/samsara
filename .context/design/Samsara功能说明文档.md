# 1. 产品概述

**Samsara 是一个自托管、可安全自我改进的个人智能体运行时。** 用户通过聊天渠道（Telegram/WhatsApp/WebChat 等）或终端与它交互；它会在使用中持续沉淀技能与记忆，越用越好用、越用越便宜。

三条价值承诺（对应主文档 §1.3）：

| 承诺 | 用户可感知的含义 |
|---|---|
| **简单便捷** | 第一天只需会"说话"：不选模型、不配参数、不学语法 |
| **高效准确** | 同类任务第 N 次比第 1 次更快更便宜——复利可测量 |
| **灵活性高** | 想怎么扩展就怎么扩展：插件、渠道、节点、远程机器，即兴技巧被追认而非封堵 |

目标用户：开发者与重度效率用户（自托管优先）；未来扩展至小团队。

# 3. 功能详述

## F-01 多渠道对话

**描述**：用户在任一已接入渠道与 Samsara 对话；渠道之间上下文独立（按 sessionKey 隔离），但技能与经审批的记忆全局共享。

**用户故事**：我在通勤路上用 Telegram 让它调研资料，回家在 WebChat 里继续查看结果。

**关键规则**：
- 渠道能力分级（L1–L6 表达力阶梯）：富内容自动降级——表格在 Telegram 变代码块、在 WhatsApp 变对齐文本；
- 按钮回调为签名事件，审批可在聊天中安全完成；
- Agent 可主动推送（任务完成、告警），推送时机由注意力路由器决定（半夜不打扰）。

**验收**：运行中热插拔一个渠道（拔掉 Telegram），**在途消息先持久化、再按 owner 配置的渠道回退链续投**（如 Telegram→WebChat→Email，K.8），无备选渠道时挂起、渠道恢复后续投——全程零丢失；按钮审批在账本上留签名证据。

## F-02 并行会话

**描述**：多个任务并行推进，每个会话独立上下文、独立经验分支，互不干扰。

**用户故事**：一个会话在写周报，另一个在查服务器日志，第三个在等我去开会——它们各自推进。

**关键规则**：会话间不共享内存态；写操作落各自 COW 分支；同一 sessionKey 的消息严格按序处理。

**验收**：100 并发会话，无交叉污染；关闭任一会话，环境无残留。

## F-03 子 Agent 派生

**描述**：主 Agent 可将任务拆分派生子 Agent 并行执行；子 Agent 能力只能小于父代、配额递减、深度上限默认 3 层。

**用户故事**："调研 5 家竞品"→ 5 个子 Agent 各负责一家，最后汇总成报告。

**关键规则**：授权代数（能力 ⊆、配额 <、等级 ≤）；kill 一个子 Agent = 环境完全回滚、配额归还、产出保留在分支上。

**验收**：派生树在 TUI 实时可见；配额耗尽时派生树必然终止（数学保证）；kill 后 `git status` 级别干净。

## F-04 技能系统

**描述**：Agent 成功完成复杂任务后自动沉淀技能（SKILL.md），下次同类任务直接复用；技能可被优化、归档、分享。

**用户故事**：第一次做财报分析花了 4 小时；一个月后同类任务 40 分钟——它记得怎么做。

**关键规则**：
- 新技能默认局部（本会话可见），晋升全局需过闸（体检 → 影子验证对打 → 按风险自动合并或人审）；
- 外部市场技能一律先隔离检疫，验证后激活；
- Curator 每周巡检：30 天未用转陈旧、90 天归档（只动自创技能）；
- 技能上限 15KB，每次修改留版本，可 blame 到具体任务。

**验收**：人为注入一个"坏技能"（含绕过审批的指令）被体检拦截；两个会话同时改同一技能时自动分叉、对打仲裁而非互相覆盖。

## F-05 记忆系统

**描述**：三层记忆——工作记忆（当前对话）、情景记忆（发生过的事）、语义记忆（你的偏好与事实）。

**用户故事**：第三次纠正它的日期格式后，它再也没犯过——那条偏好被"巩固"进了长期记忆。

**关键规则**：
- 语义记忆写入有闸门：陌生来源的会话不能写长期记忆；
- 每条记忆有出处（哪个任务写入的）；
- 用户可说"忘掉上周我告诉你的所有事"——精确遗忘，且误删可恢复（密钥托管期内）；
- **访客（guest）也可对自己 sessionKey 下的记忆行使被遗忘权**——数据主体权利不设信任门槛，操作留 R2 审计（INC4 裁决）；
- 不同私聊对象的记忆互相隔离。

**验收**：注入攻击伪造的"授权记忆"被写入体检拦截；遗忘操作在账本可查、可回滚。

## F-06 定时任务

**描述**：自然语言创建定时任务（"每周五 9 点出周报"），到点自动执行并投递结果。

**关键规则**：
- 任务携带创建者的权限快照；创建者权限降级 → 任务自动暂停；
- 高危任务有有效期，到期需续期；
- 错过触发可配置（跳过/补跑一次/补齐）；
- 结果通知时机由注意力路由器裁决（smart 模式）。

**验收**：重启守护进程后任务不丢（账本重放恢复）；仪表盘可见每个任务的月度调用量与预算消耗。

## F-07 工作流

**描述**：高频稳定的技能可"编译"为工作流（DAG）——执行更快更便宜；节点失败时自动降级为智能体模式现场修复，流程不停摆。

**用户故事**：跑了 50 遍的报表流程被系统提议固化；此后每次执行只需原来十分之一的成本，且某次 ERP 改版后它自己绕过了坏节点。

**关键规则**：编译由数据触发（复用 ≥50 次、成功率 ≥95%），不允许冲动手工编译；人审是原生节点类型；降级率过高会触发"反编译"建议。

**验收**：演示一次节点失败 → 自动降级 → 流程完成 → 系统给出节点修复提案。

## F-08 模型自动路由

**描述**：用户只需提供厂商密钥，系统自动发现可用模型，为每次任务选择"能胜任且最省钱"的模型。

**关键规则**：
- 从交互中无感学习（纠偏、否决、急停都是评分信号）；
- 探索在影子中进行——便宜模型先离线回放对打，验证后才正式启用，用户永不当实验品；
- 高风险任务有档位地板，省钱之手伸不进高危区。

**验收**：一个月使用后，仪表盘显示路由节省金额；"变笨"投诉率不升。

## F-09 权限模式与审批

**描述**：四档权限模式控制 Agent 的自主程度；高危修改走分级审批（PR 式审核）。

**用户故事**：日常让它放手干（自动编辑档）；今天要动生产数据库，切成"变更前确认"，每步我都点头。

**关键规则**：
- 模式是会话级的，带时效（"完全访问"默认 30 分钟、硬上限 4 小时，到期自动落回自动编辑档；数值以接口文档 §3.4 时效权威表为准）；
- 棘轮只降不升：异常时系统自动收紧；放宽只能由人操作，Agent 无法自我松绑；
- 审批分级：低风险自动通过，高风险人审，最高危双人复核；安全闸本身永远不可被修改。

**验收**：尝试通过对话诱导 Agent 切换模式 → 拒绝并告警；R3 修改无审批记录则无法合并。

## F-10 介入与急停

**描述**：任务运行中，人可随时插手——三档：排队（下次循环读取）、立即（撤销当前动作后插入指令）、急停（整体回滚）。

**用户故事**：看到它理解偏了，发一条"立即"消息纠正方向，不用杀任务重开。

**关键规则**："立即"的语义是回滚到最近安全点再插入，不会留下半截操作；owner 可介入任何会话，访客只能介入自己的；所有介入生成轨迹，成为系统改进的最强信号。

**验收**：演示"立即"介入后环境状态恰好在某个账本安全点上；介入轨迹可被月度复盘检索。

## F-11 回滚与审计

**描述**：系统的一切修改可回滚到任意历史点；一切操作可审计回放。

**用户故事**：一次升级把技能库搞乱了，一条命令回到昨天早上的状态——包括撤销"撤销"本身。

**关键规则**：账本是哈希链，篡改可被校验发现；回滚操作本身也记账；审计报告可导出。

**验收**：随机制造 10 次故障（kill 进程、拔渠道、坏修改），每次都能恢复到干净状态（对应附录 A 验收剧本）。

## F-12 远程工作区与多节点

**描述**：把远程服务器（云主机、WSL、GPU 节点）纳为工作区，任务可指定"在哪台机器的哪个目录"执行；多节点可并行、可互信直通。

**用户故事**："把上海节点的数据同步到新加坡，在那边跑训练"——一句话调度两台云主机。

**关键规则**：
- 工作区绑定节点与默认路径（默认路径不是权限边界，真实边界 = 沙箱级 × 系统用户 × 信任上限）；
- 节点互信一条命令建立（`trust link`），之后数据直连全速跑，事实异步入账；
- 节点告警时可一键熔断其全部信任边。

**验收**：跨节点任务结果正确且账本含传输记录；`unlink` 后横向通道确实关闭。

## F-13 外部生态接入（MCP / 技能市场）

**描述**：接入 MCP 工具服务器与社区技能市场，扩展能力边界。

**关键规则**：外部工具与技能默认隔离检疫，影子验证后上岗；工具描述限长防投毒；高危外部工具与人审闸绑定。

**验收**：安装一个含恶意指令的 MCP 工具 → 被隔离且系统行为不受影响。

## F-14 长任务与训练编排

**描述**：支持小时/天级任务：模型微调训练、视频渲染、批量数据处理——带检查点、断点续跑、GPU 预算。

**关键规则**：训练对象仅限外部模型（系统自身基座模型永久红线外）；训练语料带出处；完成通知经注意力路由器；GPU 支出按预估走审批。

**验收**：训练任务中途 kill 节点 → 从最近检查点恢复而非从头开始；删除某条训练语料可追溯到受影响的模型版本。

## F-15 管理界面

**描述**：三种管理界面按需取用——CLI（安装运维、脚本化）、TUI（实时观察派生树与队列）、WebUI（评审中心与仪表盘）。

**关键规则**：日常交互在聊天渠道完成；CLI 最先可用（M0）；WebUI 仅在高危评审与仪表盘场景必需。

**验收**：附录 I 优先级公式成立——90% 日常审批在渠道内消化，WebUI 不成为必经路径。

## F-16 观测导出

**描述**：可选对接自托管 Langfuse 等观测平台，复用其 trace UI 与评估基建。

**关键规则**：单向只读导出；外部平台不做真相来源；其 Prompt 管理不生效（提示词必须走内部版本树与审批）；外发第三方 SaaS 需 owner 批准。

**验收**：停掉观测平台，系统功能零影响；双账对账差异 >5% 触发告警。

# 4. 非功能需求

| 类别 | 指标 |
|---|---|
| 成本 | 自进化溢价 ≤ 30%/任务（H.4）；路由节省金额月度可见 |
| 性能 | 渠道消息首 token 延迟 ≤ 3s（旗舰档）；影子验证不侵占主系统 SLA |
| 可靠性 | 30 天无人值守 soak test 无 P0；崩溃恢复 = 重放账本 ≤ 60s |
| 安全 | 默认回环绑定；五项不变量 INV-1~5 + INV-6~8 全部可通过自动化验证 |
| 合规 | 被遗忘权端到端可演示（含训练语料溯源） |
| 规模 | 单机承载：100 并发会话、年数据 < 20GB（权威：数据模型 §11；启用附录 J 训练编排另计 +120GB/年） |

# 5. 明确不支持项（边界声明）

| 不支持 | 原因 |
|---|---|
| 自动训练/修改 Samsara 自身基座模型权重 | 哲学红线：进化走文本资产，不动大脑（附录 J） |
| 公网直接暴露（无隧道无认证） | 宪法层条款；远程访问走 Tailscale/SSH |
| Agent 自主提升自身权限等级 | INV-6 棘轮只降不升 |
| Computer Use（桌面 GUI 操作） | 已论证可行性，本期暂缓（防御前移 + VM 快照方案备档） |
| 多机分布式账本 | 单写入者前提；多机需求走附录 G 阶段二评审 |
